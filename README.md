# 💼 IT HubPro — задачи, проекты и финансы IT-компании

Система для суперадмина и рабочих: канбан-задачи с подзадачами и месячной аналитикой,
проекты, автоматическое распределение денег (20% / 5% / доля рабочего / деньги компании),
серверы, продления и уведомления. Работает как устанавливаемое приложение (PWA) на телефоне и ПК.

## Стек
- **Backend:** Django 6 + Django REST Framework + JWT (SimpleJWT), SQLite
- **Frontend:** Vue 3 + Vite + Pinia + Vue Router, vuedraggable (drag & drop, в т.ч. на сенсорных экранах), vite-plugin-pwa
- **Валюта:** тенге (₸), интерфейс на русском

---

## Запуск

### 1. Backend (порт 8000)
```bash
cd backend
../venv/Scripts/python.exe manage.py migrate      # первый раз
../venv/Scripts/python.exe manage.py seed         # демо-данные + суперадмин
../venv/Scripts/python.exe manage.py runserver 127.0.0.1:8000
```

### 2. Frontend (порт 5173)
```bash
cd frontend
npm install        # первый раз
npm run dev
```

Открыть **http://localhost:5173**

## Возможности

### Задачи (для всех)
- **Канбан-доска** как в Trello: «К выполнению → В работе → На проверке → Готово».
  Карточки перетаскиваются мышью и пальцем; на телефоне колонки листаются свайпом.
- У задачи: дедлайн, приоритет, проект, описание и **подзадачи-чеклист** с прогрессом.
- Суперадмин видит задачи всей команды, назначает их кому угодно, фильтрует по человеку и проекту.
- Рабочий видит только свои задачи, может сам заводить себе задачи (только по своим проектам).
- Уведомления в колокольчике: новая задача, дедлайн завтра / сегодня, просрочка.

### Аналитика за месяц
- Сколько задач выполнено, % в срок, просрочено, закрыто подзадач, среднее время выполнения.
- График «выполнено по дням», рейтинг команды с раскрытием списка задач каждого.
- Выгрузка отчёта в Excel (CSV) и печать. Рабочий видит свою статистику.

### Приложение на телефон (PWA)
- Сайт устанавливается как приложение: Android/Chrome — кнопка «Установить приложение»
  в меню; iPhone — Safari → «Поделиться» → «На экран „Домой“».
- Нужен HTTPS (на сервере уже настроен через certbot). Оболочка приложения кэшируется,
  данные всегда берутся с сервера.

### Суперадмин
- **Дашборд** — общая картина: поступления, деньги компании, фонды 20% и 5%, выплаты рабочим.
- **Проекты** — создание на отдельной странице в три колонки: проект и клиент → деньги
  (цена, долг рабочему, предоплата, живой расчёт распределения) → сроки, обслуживание и сервер.
  В карточке проекта: «Принять оплату», история оплат с остатком долга после каждой,
  «Выплатить рабочему» и история выплат.
- **Долги** — кто из клиентов сколько должен (с телефоном) и сколько мы должны рабочим.
- **Рабочие** — создание рабочих со своим логином.
- **Финансы** — три «корзины» денег: компания, фонд 20%, фонд 5% (приход/расход/баланс).
- **Серверы** — покупка и продление, оплата из выбранного фонда, срок «месяц/год».
- **Продления** — ежемесячные проекты, кнопка «Оплачено» сдвигает срок на месяц.
- **Колокольчик** — уведомления: сервер за 7 и за 1 день; продление проекта за 3 дня и в день оплаты.

### Тестировщик
- **Проверка** — проекты, отправленные рабочими: принять или вернуть с замечаниями;
  решает тот, кто ответил первым. Вся переписка хранится в проекте.

### Рабочий
- **Мои задачи** — личная канбан-доска.
- Сдача проекта — через «Отправить на проверку» тестировщикам.
- **Мои проекты** — назначенные проекты, свои даты, серверы.
- **Заработок** — своя доля по каждому проекту и суммарно.

## Финансовая логика
У проекта **одна цена** (например, 500 000 ₸). Клиент платит **любыми частями**:
100 000 → 200 000 → 100 000 → 100 000. Каждая оплата сохраняется в истории с датой и
комментарием, а остаток долга уменьшается. Переплатить нельзя: больше остатка долга
система не примет. Ошибочную оплату можно удалить, если её деньги ещё не потрачены.

С каждой оплаты автоматически отделяется:
- **фонд 1** (по умолчанию 20%) и **фонд 2** (по умолчанию 5%): ставки и названия настраиваются;
- **остаток** → деньги компании.

Пример: оплата **200 000 ₸** → 40 000 (20%) + 10 000 (5%) + 150 000 (компании).

**Рабочему:** в проекте указано, сколько мы ему должны. Каждая выплата записывается
вручную (сумма, дата, из каких денег) и уменьшает долг перед рабочим. Выплатить больше
долга или больше, чем есть в выбранном фонде, нельзя.

Страница **«Долги»** показывает, кто из клиентов сколько должен (проекты одного клиента
объединяются) и сколько компания должна рабочим. Ежемесячное обслуживание
оплачивается отдельно и в цену проекта не входит.

Рабочий отмечает фактическую сдачу проекта, и система показывает, сдал он
**раньше**, **вовремя** или **позже** дедлайна.

Логика покрыта тестами:
```bash
cd backend && ../venv/Scripts/python.exe manage.py test
```

## Деплой на сервер
```bash
bash deploy.sh          # macOS / Linux / Git Bash
# или в PowerShell:  powershell -ExecutionPolicy Bypass -File .\deploy.ps1
```
Скрипт собирает фронтенд, упаковывает проект (без базы и секретов), заливает на сервер и
запускает там `server-deploy.sh`, который: делает копию базы в `backups/` (10 последних),
прогоняет тесты, применяет миграции, перезапускает сервис и обновляет nginx (только свой сайт).
